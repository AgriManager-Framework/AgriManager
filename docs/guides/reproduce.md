# Reproducing the paper

Every number in the final paper traces to a row of a published CSV table, and
every table traces to scenario-level episode records produced by scoring a
named checkpoint revision on the frozen [test suite](../benchmark/test_suite.md).
This page gives the chain for each table and figure.

## The pipeline

```text
checkpoint revisions (HF, step-N)      scripted / neural policies
            │                                     │
            ▼                                     ▼
  e5_evaluate_checkpoint.sh              run_e4_anchors.sh, run_eval_*nn*_e4.sh
            │                                     │
            └──────────── result bundles ─────────┘
                              │   (per-scenario outputs + eval_manifest.json)
                              ▼
     analysis/test_suite/extract_e4.py     ──►  e4_episodes.parquet (one row per scenario)
                              │
                              ▼
     analysis/test_suite/e4_tables.py      ──►  results/tables/*.csv
                              │
                              ▼
     figure scripts                        ──►  Tier 1, 2, 3 figures
```

| Step | Script | What it does |
|---|---|---|
| Score | `entrypoints/eval/e5_evaluate_checkpoint.sh` ([Evaluation](evaluation.md)) | one bundle per checkpoint revision and setting |
| Score references | `experiments/rebuttal_confirmatory_eval/run_e4_anchors.sh`, `experiments/*/run_eval_*nn*_e4.sh` | scripted references and neural baselines on every split |
| Extract | `analysis/test_suite/extract_e4.py --data-root <result roots> --out <dir>` | reads every bundle, takes the metric each split declares as primary (`objective_reward` for most suites, `target_yield` for the T3.2 yield tuples, gross revenue for T1.3), writes one row per scenario, and checks each split's episode mean against the summary its evaluator wrote |
| Tabulate | `analysis/test_suite/e4_tables.py --episodes <dir>/e4_episodes.parquet` | selects each seed's terminal checkpoint and the three scored seeds, computes cell statistics, think versus no-think pairs (by seed and scenario), LLM versus neural and unified versus specialist comparisons (seeds independent, propagated SD), anchor gaps and normalized scores |
| Draw | Tier 1, 2, 3 figure scripts | read `e4_by_seed.csv`; one script per figure |

Which checkpoint revisions were scored, with the evaluator arguments used, is
listed in `results/scoring_manifest.tsv` (one row per run; feed it to
`entrypoints/tools/e4_score_worker.sh --queue` to re-score). The untrained
floors use directories made by `entrypoints/tools/prepare_untrained_base.py`.
`analysis/test_suite/make_figures.py` redraws the three tier figures from the
CSVs into `results/figures/`.

> **Notes.**
> 1. `extract_e4.py` expects the result roots in the layout described in its
>    docstring (`--data-root`, or `E4_DATA_ROOT`). Neural-baseline evaluations
>    are read from `experiments/*/results/nn_eval_e4/` of this checkout, or of
>    the directory given with `--nn-root`.
> 2. The figure scripts of the final paper (one per tier, same data, final
>    layout) are kept with the paper sources; `make_figures.py` draws an
>    earlier layout of the same CSVs.
> 3. The CSVs in `results/tables/` are the final tables of the paper. They use
>    the rebuilt Cycles suites throughout; `e4_cycles_v1_v2.csv` shows the
>    Cycles cells on both builds. They were assembled from two runs of
>    `e4_tables.py` whose rows do not overlap: the September 2026 scoring for
>    the other cells, and the October 2026 re-scoring for the Tier 3 cells on
>    the rebuilt Cycles suites (the T3.1 Cycles target and the T3.2 Cycles
>    tuples). `e4_tables.py` accepts a partial episode file, for example one
>    setting, and then writes only the rows it can compute.
> 4. The scenario-level episode file of 2026-09-26 and part of the per-run
>    scoring bundles of that date were lost with a storage allocation. The
>    aggregate tables survived. Per-run bundles are being regenerated by
>    re-scoring the revisions in `results/scoring_manifest.tsv`; until that
>    finishes, some cells are reproducible only from the aggregate CSVs.

### CSV columns

| File | One row per | Key columns |
|---|---|---|
| `e4_by_seed.csv` | setting × cell × method × arm × seed × target | `objective` (primary metric), `metric`, `n_scenarios`, `canonical`, `final_wso`, `total_n_kg_ha`, `total_irrig_mm`, `invalid_rate` |
| `e4_cells.csv` | setting × cell × method × arm × target | `mean`, `sd` over seeds, `n_seeds`, `lo`, `hi` |
| `e4_anchors.csv` | target | `no_action`, `heuristic_paper` (the paper's reference), `heuristic_current`, `gap_paper`, `think_best`, `think_gain`, `gap_usable` |
| `e4_normalized.csv` | arm × target | `status`, `norm_mean`, `norm_sd`, `raw_mean`, `no_action`, `heuristic_paper` |
| `e4_paired.csv` | comparison × target | `mean_diff`, `sd_over_seeds`, `seeds_positive`, `per_seed` (difference ± scenario SEM per seed) |
| `e4_vs_neural.csv`, `e4_specialist.csv` | comparison × target | `mean_diff`, `propagated_sd`, `diff_in_prop_sd`, `scenario_sem`, `n_scenarios`, `all_a_seeds_above_all_b` |

Method labels in the CSVs predate the final naming: `Ag heuristic (paper)` is
the scripted agronomic reference used in the paper and `Ag heuristic (current)`
the current code version.

## Statistics

- **Cells.** Mean and SD over the three training seeds of each arm; each
  seed's value is its mean over the scenarios of the split.
- **Think versus no-think.** Paired by seed (the arms share the training seed)
  and by scenario; `seeds_positive` counts seeds with a positive difference.
- **Between methods** (LLM versus neural, unified versus specialist). Seeds are
  treated as independent; the difference is reported in units of the
  propagated SD, `sqrt(sd_a² + sd_b²)`, with `all_a_seeds_above_all_b` as a
  rank check.
- **Confirmatory versus exploratory.** Three-seed test-suite results are
  confirmatory. Results available only on validation or from one seed are
  exploratory and labelled as such: training curves, the T1.2 per-crop
  breakdown, the single-seed PPO `n8` cells on T1.1, and the backbone
  comparisons (Llama-3.2 and others on T3.2).

## Which checkpoint and seed

| Choice | Rule |
|---|---|
| Checkpoint | the terminal revision of each run (`step-N`, the highest N); for a run stopped early by the rollout filter, its stop step |
| Seeds | three per arm; the seed numbers are listed in [Training](training.md#paper-runs-and-seeds) |
| Decoding | greedy (`temperature=0`), one pass |
| Response format | the one the checkpoint was trained with, read from its `run_manifest.json` |

Checkpoint repositories and revisions are listed per arm in
[Models and data](../release/models_and_data.md).

## Re-running everything

| Stage | Cost (paper scale) | Where it ran |
|---|---|---|
| Build all suites | CPU hours | batch CPU nodes |
| Train one language-model arm (200 steps) | GPU node (the replicate scripts use two GPUs) | batch GPU nodes |
| Score one checkpoint on its setting | one GPU; the scoring worker plans 75 minutes per task until it has measured one | batch GPU nodes |
| Scripted references on every split | CPU | batch CPU nodes |
| Extract and tabulate | CPU, minutes | any machine |

*Not executed for this documentation revision: the pipeline was last run on
the cluster on 2026-09-26 and partly re-run in October 2026.*
